## 用户需求

仅处理现有系统的基础层问题，不继续补完整业务功能。重点是把通用交互、命令绑定、页面响应和基础稳定性打好，减少“点了没反应”“提示成功但实际没做事”“双向绑定直接报错”这类问题。

## Product Overview

保持现有桌面界面结构和页面布局不变，不额外扩展复杂页面。优化后应呈现为：关键按钮可正常触发、日期点击与切换可用、设置页与管理页反馈更清晰、页面整体更稳定、不容易因绑定问题中断使用。

## Core Features

- 补齐分页、搜索、刷新等通用页面基础命令
- 修复转换器回写异常，避免双向绑定直接崩溃
- 接通物流、结算、系统设置、总部管理、工作计划等页面已有命令
- 将缺少完整页面的入口改为明确提示，避免无响应
- 修复工作计划日期点击和月份切换链路
- 清理明显误导性的“假成功”提示，改为最小可用行为或清晰说明

## Tech Stack Selection

- 继续沿用已确认的现有项目栈：`.NET 8 WPF`、CommunityToolkit.Mvvm、EF Core、SQLite
- 保持当前分层结构不变：`PRO.Desktop` 为本次主要改动范围，不新增新的大型架构模块

## Implementation Approach

本轮只做“基础通路修复”，不扩展业务闭环。优先复用现有 ViewModel 命令和页面结构，通过补齐基类能力、修正转换器、补绑 XAML、修复事件链路来提升稳定性，避免继续扩大改动面。

关键决策：

- `PagedViewModelBase` 只补缺失的搜索/分页基础能力，不重做列表架构
- `CommonConverters.cs` 的 `ConvertBack` 统一改为安全返回，避免运行时异常传播
- 对已有命令但未绑定的按钮直接接线；对缺完整页面的入口只做明确提示，不伪造功能
- `HeadquartersAdminViewModel` 中占位式“成功”改成可验证的最小行为或清晰不可用提示，避免误导
- `WorkScheduleView.xaml.cs` 通过当前日历项正确取值并调用已有命令，修复点击链路

性能与可靠性：

- 本轮以界面稳定性为主，新增逻辑应保持 O(1) 或页面现有查询复杂度，不引入额外全量扫描
- 避免在 UI 线程内加入长等待、长延迟或后台轮询
- 保持向后兼容，不改动数据库结构，不扩散到客户/订单等业务规则层

## Implementation Notes

- 优先改已有文件中的最小闭环，避免新增页面和无关重构
- 所有“未实现”入口都应给出明确提示，而不是静默失败或假成功
- `ConvertBack` 优先返回 `Binding.DoNothing`、`DependencyProperty.UnsetValue` 或安全默认值
- 对按钮绑定优先使用现有 `RelayCommand` 生成命令，避免重复写事件代码
- 修复后需至少进行一次解决方案构建验证基础层改动未引入新错误

## Architecture Design

本次仍沿用当前桌面端 MVVM 结构：

- `ViewModels/BaseViewModels.cs`：通用分页、搜索、刷新命令基础
- `Converters/CommonConverters.cs`：统一处理界面绑定转换安全性
- `Views/*.xaml`：补齐页面按钮与命令绑定
- `Views/WorkScheduleView.xaml.cs`：修复少量必须保留的界面事件桥接
- `ViewModels/OtherViewModels.cs`：承接页面已有命令、最小提示和基础交互逻辑
