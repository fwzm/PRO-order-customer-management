## User Requirements

根据指定功能需求文档，对当前 PRO 订单与客户管理系统进行完整功能核查，确认所有模块是否按要求实现；对未实现、实现不完整、可用性不足或存在缺陷的内容进行补全与改善；完成后进行测试，发现并修复问题。

## Product Overview

PRO 是面向多分公司使用的原生桌面订单与客户管理系统，界面需专业、简洁、易用，支持多角色权限、分公司与区域数据隔离、离线使用、自动同步、操作追溯和一键部署。系统通过左侧纯文字导航和顶部浏览器式标签页组织功能，同一功能只打开一个标签并保留页面状态，所有列表类界面支持刷新、搜索、筛选、分页和导出。

## Core Features

- 系统设置与总部管理：普通设置、组织架构、企业微信配置、Webhook、备份恢复、同步配置、数据库与接口配置、权限分配、关闭行为设置。
- 客户管理：客户新增、编辑、软删除、查询、导出、查重合并、大客户与细分客户层级、客户同步、数据隔离。
- 订单管理：订单创建、编辑、查询、导出、收款状态、状态流转、配送分配、草稿自动转正、修改记录追溯。
- 产品与库存：产品新增编辑、分类、库存、价格权限控制、库存为零仍可下单。
- 物流管理：配送员管理、订单池、手动分配、预留自动分配、高德路径规划格式导出。
- 财务结算：按时间范围结算、不可逆锁定、PDF生成、近30天记录、单个和批量下载。
- 工作计划：管理员排班、员工详细计划、5分钟时间段、草稿本地保存、发布通知、变动标识。
- 非功能：敏感信息加密、操作日志本地保存、结算时同步日志、性能达标、无警告报错、稳定运行。

## Tech Stack Selection

- 当前项目已确认为 `.NET 8 WPF` 原生 Windows 桌面应用，继续沿用现有四层结构：`PRO.Domain`、`PRO.Application`、`PRO.Infrastructure`、`PRO.Desktop`。
- UI/MVVM：WPF、CommunityToolkit.Mvvm、MaterialDesignInXAML、HandyControl。
- 本地数据：SQLite + Entity Framework Core，现有入口为 `ProDbContext` 与仓储类。
- 外部同步：现有 NocoDB REST API 客户端、字段同步服务、企业微信 HTTP 服务继续复用并补强。
- 导出与文档：ClosedXML 用于 Excel，高德路径规划导出；QuestPDF 用于结算 PDF。
- 日志与安全：Serilog、Windows DPAPI、BCrypt 继续作为日志、敏感信息加密和密码哈希基础。

## Implementation Approach

先建立“需求文档功能点 → 当前代码实现 → 缺口/风险 → 修复结果”的核查矩阵，再按“构建阻塞优先、用户可见功能优先、同步和日志兜底、测试验证闭环”的顺序实施。
本次不重构为全新架构，不引入 Web 化方案；优先修复现有 View/ViewModel/Infrastructure 中已存在但未绑定、未落地或易崩溃的功能，降低改动范围。

关键决策：

- 优先修复明显运行时问题：未绑定按钮、`ConvertBack` 抛异常、结算/物流/组织架构入口不可用、工作计划点击无效。
- 同步能力采用离线优先与可恢复设计：本地操作先落库和记录日志，再标记待同步；联网、手动同步、定时同步、关闭前同步统一走同步服务。
- 对外部服务无有效凭证时不阻塞本地功能：NocoDB/企业微信测试连接失败应给出清晰状态，不影响离线业务操作。
- 对 10 万级订单列表避免全量加载：所有列表查询先过滤再 `Count/Skip/Take`，必要处使用 `AsNoTracking`，避免导出和结算在 UI 线程长时间阻塞。
- 对财务、订单、权限等核心功能保持审计性：增删改、状态流转、结算、同步等操作统一写入本地操作日志。

## Implementation Notes

- 先运行构建并记录当前错误；修复时避免无关重命名和大规模样式重做。
- ViewModel 中已有命令但 XAML 未绑定的，优先补绑定；没有命令的再补最小可用命令。
- 所有数据库查询必须保留分公司/区域权限过滤，尤其是客户、订单、配送员、结算、工作计划和组织架构。
- 同步和备份必须后台执行并带状态提示；不要在 UI 命令中使用长时间 `Task.Delay` 阻塞用户流程。
- 敏感字段只保存加密值，界面展示采用掩码或空值回填，日志不得输出密钥、密码、Token、Webhook 完整地址。
- 外部集成测试分为本地单元/模拟测试和真实配置可用时的连接测试，避免无凭证导致整体验收失败。

## Architecture Design

沿用当前分层架构：

- `PRO.Domain`：实体、枚举、业务状态字段。
- `PRO.Application`：DTO、接口、跨模块服务契约。
- `PRO.Infrastructure`：EF Core、SQLite、NocoDB、企业微信、加密、备份、同步、日志服务实现。
- `PRO.Desktop`：WPF Views、ViewModels、Converters、Resources 和用户交互。

核心数据流：

1. 用户在桌面界面操作。
2. ViewModel 校验权限和输入。
3. 写入 SQLite，本地设置同步状态和操作日志。
4. 后台同步服务按策略上传/拉取外部数据并处理冲突。
5. UI 刷新当前分页数据并显示同步/错误状态。

## Agent Extensions

### Skill

- **docx**
- Purpose: 读取并复核用户提供的 Word 功能需求文档，形成可追踪功能清单。
- Expected outcome: 生成完整需求核查矩阵，避免遗漏模块和边界规则。

- **NocoDB API**
- Purpose: 指导和验证 NocoDB REST API v3 的连接、字段同步、记录同步和错误处理实现。
- Expected outcome: 同步逻辑与字段映射符合自部署 NocoDB 使用方式，并能安全处理无凭证或连接失败场景。

- **企业微信套件**
- Purpose: 对齐企业微信配置、通讯录同步、客户同步、消息通知和 Webhook 管理能力。
- Expected outcome: 企业微信相关功能具备可测试的配置、同步、发送和错误提示流程。

- **PDF 文档生成**
- Purpose: 优化财务结算 PDF 的结构、视觉层次、签字区、明细表和导出质量。
- Expected outcome: 结算 PDF 满足专业、可打印、可归档的业务交付标准。

- **xlsx**
- Purpose: 校验客户、订单、产品、物流高德路径规划等 Excel 导出格式。
- Expected outcome: 导出的表头、字段顺序、格式和高德路径规划要求一致。

### SubAgent

- **code-explorer**
- Purpose: 跨目录核查 View、ViewModel、服务、实体、仓储和配置之间的实现链路。
- Expected outcome: 快速定位功能缺口、未绑定命令、未实现服务、权限和同步风险点。
